# 实时协同编程的未来方向

> 这篇整理自早期的一些想法。AI Agent 这两年变化很快，部分内容已经有些过时，仅作为方向性参考。

在了解 Y.js、CRDT 之后，你已经掌握了构建实时协同应用的基础。下面是一些尚未充分解决、可能值得继续探索的方向。

## 1. AI 作为协作参与者

目前 Copilot 这类工具更像服务单个用户的助手。一个可能的延伸是：把 AI 作为团队协作中的一员，拥有自己的光标，能被 `@` 召唤，参与编写代码，并在其他人编辑时给出非侵入式的提示，例如指出命名问题或性能隐患。

多人和 AI 在同一个协同环境里共存，会带来新的状态同步和权限问题。

## 2. 语义层面的合并

CRDT 擅长在字符层面合并修改，保证每个人文本一致，但它不理解代码的含义。Git 遇到冲突时会直接停下来，让人处理冲突标记。

如果能结合语法和语义理解，合并工具就可以识别改动意图。例如你把函数 `getData()` 重命名为 `fetchUserData()`，而队友在 `getData()` 里加了参数，语义合并可以自动得到 `fetchUserData(newParameter)`，而不报冲突。

## 3. 更丰富的协作感知

现在的协作工具基本只显示光标位置。信息太少，有时还会带来压力：光标停在某一行，未必代表什么。

可以设计更丰富的感知方式，让协作者了解彼此的状态又不被打扰。例如某人长时间停留在某个代码块，可以用较弱的视觉提示表示他在思考；有人选中一段代码准备重构，也可以提前给出提示。

## 4. 编程教育场景

编程教学目前主要靠屏幕共享，或者老师走到学生旁边帮忙排查。实时协同可以提供更细粒度的课堂形式：老师同时看到所有学生的光标，发现有人卡住时进入他的一对一视图单独指导，也可以把学生分成若干协同子房间，实时查看各组进度。

## 5. 单人开发与多人协作的衔接

单人开发和团队协作现在是两种割裂的状态：先在本地开发，再通过 `git push` 和 Pull Request 异步同步。

如果能降低两者之间的切换成本，求助会变得很简单：你在自己的分支上遇到 Bug，直接开启一个协同会话把链接发给别人，对方进入一个和你环境一致的临时空间一起调试，结束后改动仍留在你的本地分支，再按正常流程提交 PR。

---

这些方向有的偏算法，有的偏 AI，有的偏人机交互。一个比较有潜力的延伸是把 RCP 的思想用到 Multi-Agent 上，让多个 Agent 像协作者一样共享和同步状态，这部分目前还有不少可做的空间。
