# 数据模型与状态同步（你看到的“同步”，其实是两条线）

很多新同学第一次跑通协作后，会遇到一种“说不清的同步问题”：

- 文本能同步，但光标不显示。
- 光标能显示，但选区位置不准。
- 你打字时对方看得到，但偶尔会“抖一下”或者被回写。

这些现象背后其实是两条不同的同步线：

1. **文档内容同步**：你在文件里插入/删除的字符（Yjs 文档 update）。
2. **协作态同步**：光标、选区、可见区域、正在看哪个文件（Awareness / Presence）。

这一页会把两条线都讲清楚，并把关键代码片段贴出来，让你能把“现象”对齐到“原因”。

## 一、文档内容同步：本地改动怎么变成网络消息

在 `open-collaboration-yjs` 里，`OpenCollaborationYjsProvider` 做的是“桥接”工作：

- 本地 Yjs 文档更新 -> 编码 -> 通过 protocol 的 `sync.dataUpdate` 发出去。
- 收到远端 `dataUpdate` -> 解码 -> 应用到本地 Yjs 文档。

下面这段代码就把两边都写明白了。

```ts
private ocpDataUpdateHandler(origin: string, update: types.Binary): void {
    const decoder = this.decode(update);
    const encoder = encoding.createEncoder();
    const syncMessageType = syncProtocol.readSyncMessage(decoder, encoder, this.doc, origin);
    if (syncMessageType === syncProtocol.messageYjsSyncStep1) {
        this.connection.sync.dataUpdate(origin, this.encode(encoder));
    }
}

private yjsUpdateHandler(update: Uint8Array, origin: unknown): void {
    if (origin !== this) {
        const encoder = encoding.createEncoder();
        syncProtocol.writeUpdate(encoder, update);
        this.connection.sync.dataUpdate(this.encode(encoder));
    }
}
```

读这段时建议重点看两个点：

- `origin !== this`：这是防止“我自己应用的更新又回头广播一次”的关键。
- `syncStep1` 分支：这是新加入者追齐状态时的握手步骤之一。

如果你遇到“文本同步偶尔停一下再追上”，通常不是编辑器事件没触发，而是握手或重连时的同步阶段在跑。

## 二、协作态同步：光标/选区为什么单独一条链路

文本内容是“持久状态”，但光标/选区更像“临时状态”。

在项目里，awareness 的同步也是由 provider 做桥接：

- 本地 awareness 变更 -> `sync.awarenessUpdate()`
- 收到远端 awareness -> `applyAwarenessUpdate()`

（你可以把它理解成：awareness 不是写进文件内容的，它只是“大家此刻在看哪里”。）

## 三、为什么还要做 NormalizedText：CRLF/LF 的坑不是段子

如果 Host 在 Windows（CRLF）编辑，而 Guest 在 macOS/Linux（LF）编辑，单纯用“字符偏移”会出问题。

`YjsNormalizedTextDocument` 的核心思想是：

- Yjs 内部按统一规则存（normalized）
- VS Code 侧按各自平台的换行习惯展示（original）
- 两者之间通过 offset 映射保证“选区位置”不漂

下面这段代码就是 offset 映射的关键：

```ts
originalOffset(normalizedOffset: number): number {
    const lineOffset = this.findLineOffset(normalizedOffset, 'normalized').offsets;
    const delta = normalizedOffset - lineOffset.normalized;
    const originalOffset = lineOffset.offset + delta;
    return originalOffset;
}

private async observe(event: Y.YTextEvent, callback: YjsTextDocumentChangedCallback): Promise<void> {
    if (event.transaction.local) {
        return;
    }
    const hasCR = this._text.includes('\r');
    const changes = YTextChangeDelta.toChanges(event.delta);
    const changeSet: YTextChange[] = [];
    for (const change of changes) {
        changeSet.push({
            start: this.originalOffset(change.start),
            end: this.originalOffset(change.end),
            text: this.normalize(change.text, hasCR),
        });
    }
    // ...
}
```

如果你在协作时看到“选区不准”“光标跳来跳去”，十有八九不是 awareness 本身坏了，而是 offset 映射和换行规范化出了偏差。

## 四、VS Code 侧怎么把选区变成“可同步的数据结构”

在 `open-collaboration-vscode` 里，选区同步不是直接发“第 N 个字符”，而是发相对位置（relative position）。

这段代码是同步选区的核心：

```ts
const ytext = this.yjs.getText(path);
const normalizedDocument = this.getNormalizedDocument(editor.document, path);
const selections: types.RelativeTextSelection[] = [];
for (const selection of editor.selections) {
    const start = normalizedDocument.normalizedOffsetAt(selection.start);
    const end = normalizedDocument.normalizedOffsetAt(selection.end);
    const direction = selection.isReversed
        ? types.SelectionDirection.RightToLeft
        : types.SelectionDirection.LeftToRight;
    const editorSelection: types.RelativeTextSelection = {
        start: Y.createRelativePositionFromTypeIndex(ytext, start),
        end: Y.createRelativePositionFromTypeIndex(ytext, end),
        direction
    };
    selections.push(editorSelection);
}
```

这里有两个“新手必读”的点：

- `normalizedOffsetAt()`：先把 VS Code 的 position 映射到 normalized offset。
- `createRelativePositionFromTypeIndex()`：用相对位置而不是绝对 offset，避免并发编辑导致的漂移。

## 常见问题：问题到底在“同步层”还是“文件系统代理层”？

遇到同步问题时，你可以用一个粗暴但有效的分界方法：

- **文件能不能打开/读目录**：优先看文件系统代理（见 [文件系统代理与远程访问](/collaboration_tools/核心模块详解/open-collaboration-vscode模块/文件系统代理与远程访问.md)）。
- **文件打开了但内容不一致**：优先看文本同步（provider + normalized text）。
- **内容一致但光标/选区奇怪**：优先看 awareness + offset 映射。

## Summary
- 文本同步和光标同步是两条链路：一个是 Yjs update，一个是 awareness。
- `origin !== this` 是避免回环广播的关键条件。
- CRLF/LF 的差异会直接影响 offset，`YjsNormalizedTextDocument` 在这里不是“锦上添花”，而是救命。
- VS Code 侧同步选区用的是相对位置（relative position），这是为了在并发编辑下保持稳定。
