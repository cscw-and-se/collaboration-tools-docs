# 简易登录（团队默认使用方式：如何更改最安全）

simple login 在这个项目里不是“随便写写的 demo”，而是一套完整可用的开发/内网认证链路：

- 客户端拿到 pollToken。
- 浏览器打开登录页（或客户端用 form provider 自己渲染表单）。
- 用户填 name/email 提交。
- server 触发认证事件，统一签发 JWT。
- 客户端轮询拿到 loginToken。

这一页只讲你们团队最常用的那条路径，并给出“如果要扩展字段/限制访问”应该从哪改。

## 1) 表单长什么样：server 端定义了 fields

simple login 的表单不是前端写死的，而是 server 通过 provider 描述出来的：

```ts
fields: [
    {
        name: 'user',
        required: true,
        placeHolder: { message: 'Your user name that will be shown to all session participants', code: Info.Codes.UsernamePlaceholder, params: [] },
        label: { message: 'Username', code: Info.Codes.UsernameLabel, params: [] }
    }, {
        name: 'email',
        required: false,
        placeHolder: { message: 'Your email that will be shown to the host when joining the session', code: Info.Codes.EmailPlaceholder, params: [] },
        label: { message: 'Email', code: Info.Codes.EmailLabel, params: [] }
    }
]
```

这段代码解决的问题是：“客户端不需要写死表单结构”。如果你要扩展字段（比如学号/组织），建议从这里加字段，并在 POST handler 做校验。

## 2) 提交之后 server 做什么：校验 + fire 事件

server 的 POST handler 只做轻量校验，然后 fire 认证事件：

```ts
const token = req.body.token as string;
const user = req.body.user as string;
const email = req.body.email as string | undefined;

if (!token) { res.status(400); res.send('No token provided'); return; }
if (!user)  { res.status(400); res.send('No user provided'); return; }

await Promise.all(this.authSuccessEmitter.fire({ token, userInfo: { name: user, email, authProvider: 'Unverified' } }));
res.send('Ok');
```

这段代码解决的问题是：“provider 只负责提供 userInfo，不负责签 JWT”。

## 3) JWT 从哪里来：仍然是 `confirmUser()` 统一签发

签 JWT 的唯一收口是 `CredentialsManager.confirmUser()`：

```ts
const registeredUser = await this.userManager.registerUser(user);
const userClaim: User = {
    id: registeredUser.id,
    name: registeredUser.name,
    email: registeredUser.email,
    authProvider: registeredUser.authProvider
};
const jwt = await this.generateJwt(userClaim);
auth.update(jwt);
return jwt;
```

这段代码解决的问题是：“无论 simple login 还是 OAuth/Keycloak，JWT 都一致”。

## 我们建议你怎么改（最安全的改动点）

- 想加字段：改 provider `fields` + POST handler 校验 + `userInfo`。
- 想限制访问：在 POST handler 增加白名单校验（例如 email domain/名单），校验失败直接 400。
- 不建议：在 endpoint 内部自己签 JWT（会导致 token 行为分裂，排障难）。

## Summary

- simple login 这条链路非常适合开发/内网：最快把协作主线跑通。
- 表单结构由 server provider 描述；提交后只 fire 事件；JWT 由 `confirmUser()` 统一签发。
- 二开最安全的改动点是“扩展 fields 与校验”，而不是改 token/poll/JWT 主链路。
