# 通信安全（消息级加密、压缩协商、未加密消息的处理）

这个项目的协作通信不是“把 JSON 直接丢 WebSocket”这么简单。它至少有三层你需要知道的现实约束：

1. 连接接入时必须带 JWT 与公钥（否则 server 直接拒绝）。
2. request/broadcast 默认必须是加密消息（server 端会拒绝未加密消息）。
3. 支持压缩协商（`x-oct-compression`），server 会记录客户端能力。

这一页不展开密码学细节，只把这三件事如何落在代码里讲清楚，方便你排障与二开时不踩坑。

## 1) 连接阶段：为什么必须带 `x-oct-public-key`，以及压缩如何协商

server 在 `connectChannel()` 里要求 JWT + public key，并读取压缩能力：

```ts
const publicKey = headers['x-oct-public-key'];
if (!publicKey) {
    throw this.logger.createErrorAndLog('No encryption key set');
}
let compression = headers['x-oct-compression']?.split(',');
if (compression === undefined || compression.length === 0) {
    compression = ['none'];
}
const client = headers['x-oct-client'] ?? 'unknown';
```

这段代码解决的问题是：“在连接建立的第一时间把加密与压缩能力说清楚”。你排查连接问题时，如果看到 server 端报：

- `No encryption key set`：客户端没有按协议带公钥。
- `No JWT auth token set`：客户端还没拿到/没带上 JWT。

## 2) 消息入口：未加密的 request/broadcast 会被直接丢弃

server 的 `PeerImpl.receiveMessage()` 会对 request 与 broadcast 做强制加密要求：

```ts
} else if (protocol.RequestMessage.isAny(message)) {
    if (!protocol.Message.isEncrypted(message)) {
        this.logger.warn(`Received unencrypted request from: '${this.id}'`);
        return;
    }
    // ...
} else if (protocol.BroadcastMessage.isAny(message)) {
    if (!protocol.Message.isEncrypted(message)) {
        this.logger.warn(`Received unencrypted broadcast from: '${this.id}'`);
        return;
    }
    this.messageRelay.sendBroadcast(this, message);
}
```

这段代码解决的问题是：“把安全要求写死在入口处”。二次开发时最不建议做的事之一就是放宽这里的校验，否则未加密消息会混进系统，排障与风险都会指数级上升。

## 3) 加密广播：为什么要按目标 peer 裁剪 key

加密广播消息会携带多把 key（每个目标 peer 一把）。server 广播时会按目标裁剪，只给 peer 发它自己的那把 key：

```ts
const peerKey = message.metadata.encryption.keys.find(e => e.target === peer.id);
if (peerKey && BroadcastMessage.isEncrypted(message)) {
    const messageWithSingleKey: EncryptedBroadcastMessage = {
        ...message,
        metadata: {
            ...message.metadata,
            encryption: { keys: [peerKey] }
        }
    };
    peer.channel.sendMessage(messageWithSingleKey);
}
```

这段代码解决的问题是：“广播要发给所有人，但不应该把所有人的 key 都发给每个人”。这既是安全考量，也是带宽与性能考量。

## Summary

- 连接接入时强制 JWT + public key，并协商压缩能力。
- server 入口处会丢弃未加密 request/broadcast，这是系统默认安全边界。
- 加密广播会按目标裁剪 key，避免不必要的密钥分发。
