# 消息编码机制（content 如何从对象变成 Uint8Array，再变回来）

协议层的“编码”很容易被误解成“把整条消息打包成二进制”。实际上在 `open-collaboration-protocol` 里，你可以把编码理解成两层：

1. **content 编码**：`message.content` 从对象 → 二进制（MessagePack）
2. **envelope 编码**：整个 `Message`（包含 version/kind/metadata/content）从对象 → 二进制（同样也是 MessagePack）

前者由 `Encoding.encode/decode` 直接负责；后者主要发生在 `AbstractBroadcastConnection.write()`/`handleMessage()` 里（它会把“整条 message 对象” encode 后写入 transport）。

## 1. content 编码：`Encoding.encode/decode` 就是两行

最底层的编码定义在 `packages/open-collaboration-protocol/src/messaging/encoding.ts`：

```ts
import * as msgpack from 'msgpackr';

export namespace Encoding {
    export function encode(message: unknown): Uint8Array {
        return msgpack.encode(message);
    }
    export function decode(data: Uint8Array): unknown {
        return msgpack.decode(data);
    }
}
```

这段代码解决的问题是：“把 JS 对象变成 `Uint8Array`，反过来也能还原回来”。

- 上游怎么到这：`Encryption.encrypt()` 会先对 `message.content` 做 encode；`AbstractBroadcastConnection.write()` 会对整条 message 做 encode。
- 下游会发生什么：encode 的结果可能再被压缩/加密；decode 的结果会进入 `handleMessage()` 的 kind 分支。

## 2. message envelope：method + params 是怎么被放进 content 的

以 request 为例，`RequestMessage.create()` 会把 `method` 与 `params` 放进 content，并挂上统一的默认 metadata（源码：`packages/open-collaboration-protocol/src/messaging/messages.ts`）：

```ts
export namespace RequestMessage {
    export function create(signature: RequestType<any, any> | string, id: number | string, origin: MessageOrigin, target: MessageTarget, params?: any[]): RequestMessage {
        return {
            version: VERSION,
            id,
            metadata: DEFAULT_METADATA,
            origin,
            target,
            kind: 'request',
            content: {
                method: typeof signature === 'string' ? signature : signature.method,
                params
            }
        };
    }
}
```

这段代码解决的问题是：“把一条语义调用（method + params）变成一条可传输的协议消息（kind + metadata + content）。”

注意这里的一个非常实用的点：你可以传 `RequestType`（强类型）也可以传字符串（更灵活，但更容易写错）。工程上通常建议**对外暴露强类型**，内部特殊情况才用字符串。

## 3. 强类型 method：`RequestType/BroadcastType/NotificationType` 到底是什么

`open-collaboration-protocol/src/messaging/messages.ts` 里有三个“签名类”，它们本质上只保存 `method` 字符串，同时通过 TypeScript 的 phantom type 约束 params/return：

```ts
export class BroadcastType<P extends unknown[] = []> extends AbstractMessageSignature {
    public readonly _?: ['broadcast', P, void];
    constructor(method: string) { super(method); }
}
export class RequestType<P extends unknown[], R> extends AbstractMessageSignature {
    public readonly _?: ['request', P, R];
    constructor(method: string) { super(method); }
}
export class NotificationType<P extends unknown[]> extends AbstractMessageSignature {
    public readonly _?: ['notification', P, void];
    constructor(method: string) { super(method); }
}
```

这段代码解决的问题是：“让 `sendRequest(Messages.FileSystem.ReadFile, target, path)` 在编译期就能约束参数与返回值”，从而减少 runtime 错误。

## 4. 什么时候“整条 message”会被 encode

在你真正写入 transport 前，协议层会把整个 `Message` 对象 encode 成二进制（而不是只 encode content）。你从 `sendNotification()` 的实现就能看出来：它先创建一个“对象形式的 message”，然后交给 `write()`，由 `write()` 再统一 encode 并写入 transport（源码：`packages/open-collaboration-protocol/src/messaging/abstract-connection.ts`）：

```ts
async sendNotification(type: msg.NotificationType<any> | string, target: msg.MessageTarget, ...parameters: any[]): Promise<void> {
    await this._ready.promise;
    const message = msg.NotificationMessage.create(type, '', target, parameters);
    if (target === '') {
        await this.write(message);
    } else {
        const encryptedMessage = await Encryption.encrypt(message, {
            symmetricKey: this.symKey,
            cache: this.encryptionKeyCache
        }, this.getPublicKey(target));
        await this.write(encryptedMessage);
    }
}
```

这就是所谓的 envelope 编码：version/kind/metadata/content 都会被序列化进二进制帧。

## Summary

- `Encoding.encode/decode` 是“最低层的序列化”，用 MessagePack 把对象与 Uint8Array 互转。
- `RequestMessage.create()` 把 method/params 放进 content，并挂上默认 metadata，形成一条完整 envelope。
- `RequestType/BroadcastType/NotificationType` 主要提供类型签名约束，不是复杂的 runtime 逻辑。
- 写入 transport 时会 encode 整条 message 对象，不只是 content。
