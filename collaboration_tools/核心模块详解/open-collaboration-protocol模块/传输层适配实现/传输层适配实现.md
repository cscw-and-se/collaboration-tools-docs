# 传输层适配实现（谁负责重连，什么时候算断开）

在 `open-collaboration-protocol` 里，传输层（transport）的定位很克制：它只负责“把二进制数据发出去/收进来”，以及暴露一些生命周期事件。**真正的消息编码、加密、路由、request/response 对齐，都在 messaging 层完成**。

你读这一页时，建议带着三个问题：

1. transport 接口到底提供了哪些承诺？
2. Socket.IO 与原生 WebSocket 在“重连/断线”的语义上差在哪里？
3. 协议层是怎么把 transport 的 disconnect/reconnect 事件抬升为 `connection.onDisconnect/onReconnect` 的？

## 1. transport 接口：协议层只依赖这个契约

传输接口定义在 `packages/open-collaboration-protocol/src/transport/transport.ts`：

```ts
export type ConnectionWriter = (data: Uint8Array) => Promise<void>;
export type ConnectionReader = (cb: (data: Uint8Array) => void) => void;

export interface MessageTransportProvider {
    readonly id: string;
    createTransport(url: string, headers: Record<string, string>): MessageTransport;
}

export interface MessageTransport {
    readonly id: string;
    write: ConnectionWriter;
    read: ConnectionReader;
    dispose(): void;
    onReconnect: Event<void>;
    onDisconnect: Event<void>;
    onError: Event<string>;
}
```

这段代码解决的问题是：“让协议层在不关心底层库的情况下完成收发”。因此你在 protocol 侧二开，99% 的情况下都不需要碰 transport；而你要接入一种新传输方式时，就只需要实现这几个方法/事件。

## 2. Socket.IO：断线不等于离线（30 秒窗口）

Socket.IO 的实现（`packages/open-collaboration-protocol/src/transport/socket-io-transport.ts`）给了一个非常明确的语义：**disconnect 发生时先不立刻宣布断开，而是给 30 秒重连窗口**。

```ts
this.socket.on('disconnect', () => {
    this.ready = new Deferred();
    // Give it 30 seconds to reconnect before firing the disconnect event
    this.disconnectTimeout = setTimeout(() => {
        this.onDisconnectEmitter.fire();
        this.disconnectTimeout = undefined;
    }, 30_000);
});
this.socket.io.on('reconnect', () => {
    if (this.disconnectTimeout) {
        clearTimeout(this.disconnectTimeout);
        this.disconnectTimeout = undefined;
        this.ready.resolve();
    }
    this.onReconnectEmitter.fire();
});
```

这段代码解决的问题是：“网络抖一下时，协作会话不要立刻崩掉”。对协作这种长连接场景来说，这个行为非常关键：它直接影响到你在 VS Code 里看到的“是否掉线/是否要清理 workspace”等上层逻辑。

## 3. 原生 WebSocket：没有重连事件，断开就是断开

原生 WebSocket 的实现（`packages/open-collaboration-protocol/src/transport/websocket-transport.ts`）更朴素：没有自动重连，因此 `onReconnect` 明确返回 `Event.None`：

```ts
readonly id = 'websocket';

private onDisconnectEmitter = new Emitter<void>();
private onErrorEmitter = new Emitter<string>();
private ready = new Deferred();

get onReconnect(): Event<void> {
    return Event.None;
}
get onDisconnect(): Event<void> {
    return this.onDisconnectEmitter.event;
}
get onError(): Event<string> {
    return this.onErrorEmitter.event;
}
constructor(protected socket: WebSocket) {
    this.socket.onclose = () => this.onDisconnectEmitter.fire();
    this.socket.onerror = () => this.onErrorEmitter.fire('Websocket connection closed unexpectedly.');
    this.socket.onopen = () => this.ready.resolve();
}
```

这段代码解决的问题是：“提供一个最薄的封装”。如果你用 WebSocketTransport，你需要在更上层决定是否实现重连（protocol 本身不会替你做）。

## 4. 协议层怎么接管这些事件：`AbstractBroadcastConnection` 把 transport 变成 connection lifecycle

协议层在 `AbstractBroadcastConnection` 的构造函数里把 transport 的事件连接起来（`packages/open-collaboration-protocol/src/messaging/abstract-connection.ts`）：

```ts
constructor(readonly options: AbstractBroadcastConnectionOptions) {
    options.transport.read(data => this.handleMessage(new Uint8Array(data)));
    options.transport.onDisconnect(() => this.dispose());
    options.transport.onError(message => {
        this.onConnectionErrorEmitter.fire(message);
        this.dispose();
    });
    options.transport.onReconnect(() => this.onReconnectEmitter.fire());
}

dispose(): void {
    this.onDisconnectEmitter.fire();
    this.onDisconnectEmitter.dispose();
    this.onErrorEmitter.dispose();
    this.messageHandlers.clear();
    this.options.transport.dispose();
}
```

这段代码解释了“为什么 transport 的断开会让 connection 直接 dispose”。也解释了一个常见现象：

- 你看到的不是“底层 socket 断了”，而是 “protocol 连接对象被 dispose 了”
- dispose 会清理 handler、释放 transport，并触发 `onDisconnect`

因此你在排障时，不要只盯着 socket 的状态，应该同时看：

- transport 发了什么 disconnect/error
- protocol 层有没有因为某个 error 提前 dispose
- 上层（vscode）是否在 onDisconnect 后执行了 workspace 清理

## Summary

- transport 的职责是最薄的：write/read + lifecycle events；协议层只依赖 `MessageTransport` 接口。
- Socket.IO 的关键语义是“30 秒重连窗口”，disconnect 不立刻触发 onDisconnect。
- 原生 WebSocket 没有重连：`onReconnect = Event.None`，断开就是断开。
- `AbstractBroadcastConnection` 把 transport 事件上抬为 connection 生命周期，并在 disconnect/error 时直接 dispose。
