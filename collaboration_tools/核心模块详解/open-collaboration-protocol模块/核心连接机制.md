# 核心连接机制（从 login 到 connect，再到“Host 允许加入”）

当你把协作系统跑起来之后，最常见的两个疑问其实是：

1. 我明明已经拿到了 roomId，为什么 Join 还要等半天？
2. 我拿到了 roomToken，为什么 connect 还是立刻断开或者一直没 ready？

这一页不从“抽象架构图”讲，而是从你最可能遇到的真实链路讲：`login()` → `createRoom()/joinRoom()` → `connect(roomToken)`。读完你应该能在代码里快速定位：到底是 HTTP 阶段的问题，还是实时连接阶段的问题，还是 Host 没点 Allow。

## 1. login：为什么要 `authenticationHandler` + poll

`ConnectionProvider.login()` 的第一步是向 server 请求一个“登录轮询 token”，然后把“如何让用户完成登录”交给上层（浏览器打开页面、弹出表单、走 OAuth 等）。源码在 `packages/open-collaboration-protocol/src/connection-provider.ts`：

```ts
async login(options: LoginOptions): Promise<string> {
    options.reporter?.({ code: 'PerformingLogin', params: [], message: 'Performing login' });
    const loginResponse = await this.fetch(this.getUrl('/api/login/initial'), {
        signal: options.abortSignal,
        method: 'POST'
    });
    const loginBody = await loginResponse.json();
    const confirmToken = loginBody.pollToken;
    const url = loginBody.auth.loginPageUrl;
    const fullUrl = url?.startsWith('/') ? this.getUrl(url) : url;
    const authController = new AbortController();
    const abortSignal = this.mergeAbortSignals(options.abortSignal, authController.signal);
    this.options.authenticationHandler(confirmToken, { ...loginBody.auth, loginPageUrl: fullUrl }).then(success => {
        if (!success) authController.abort();
    }, () => authController.abort());
    const authToken = await this.pollLogin(confirmToken, { ...options, abortSignal });
    this.userAuthToken = authToken;
    return authToken;
}
```

这段代码解决的问题是：“协议层不假设你怎么登录，只要求你能把登录流程跑起来；一旦用户完成登录，协议层就靠 poll 拿到 loginToken。”

- 上游怎么到这：客户端调用 `provider.login()`（或由 `createRoom/joinRoom` 在 `validate()` 失败时隐式触发）。
- 下游会发生什么：如果 `authenticationHandler` 失败（打不开页面/用户取消），会 `abort()` 轮询；否则进入 `pollLogin()` 一直拉状态直到拿到 token。

`pollLogin()` 本质是一个无限循环，直到 server 返回 `loginToken`（同文件）：

```ts
private async pollLogin(confirmToken: string, options: LoginOptions): Promise<string> {
    while (true) {
        const confirmResponse = await this.fetch(this.getUrl(`/api/login/poll/${confirmToken}`), {
            signal: options.abortSignal,
            method: 'POST',
        });
        if (confirmResponse.ok) {
            try {
                const confirmBody = await confirmResponse.json();
                if (types.LoginPollResponse.is(confirmBody) && confirmBody.loginToken) {
                    return confirmBody.loginToken;
                }
            } catch {
                // No token yet, keep polling
            }
        } else {
            throw await this.readError(confirmResponse);
        }
    }
}
```

你在排障时的一个小技巧：**如果 login 卡住，先看 abortSignal 有没有被触发**（上层 handler 很可能返回了 false 或抛了异常）。

## 2. create/join：为什么每次都要先 `ensureCompatibility()`

真正创建/加入房间之前，协议层会先打 `/api/meta` 做版本兼容检查（同文件）：

```ts
async ensureCompatibility(): Promise<void> {
    const metadata = await this.getMetaData();
    const serverVersion = semver.parse(metadata.version);
    if (!serverVersion) {
        throw new ServerError({
            code: 'InvalidServerVersion',
            message: 'Invalid protocol version returned by server: ' + metadata.version,
            params: [metadata.version]
        });
    }
    if (!compatibleVersions(serverVersion, this.protocolVersion)) {
        throw new ServerError({
            code: 'IncompatibleProtocolVersions',
            message: `Incompatible protocol versions: client ${this.protocolVersion.format()}, server ${serverVersion.format()}`,
            params: [this.protocolVersion.format(), serverVersion.format()]
        });
    }
}
```

这段代码解决的问题是：“避免 client/server 协议版本不兼容导致更隐蔽的运行时错误”。你看到 `IncompatibleProtocolVersions` 时，不要继续猜业务逻辑，先把版本对齐。

## 3. createRoom：登录不合法时会自动触发 login

`createRoom()` 的逻辑你可以读成三步：兼容性检查 → 认证有效性检查 → 调 `/api/session/create`。源码（同文件）：

```ts
async createRoom(options: CreateRoomOptions): Promise<types.CreateRoomResponse> {
    await this.ensureCompatibility();
    const valid = await this.validate();
    let loginToken: string | undefined;
    if (!valid) {
        loginToken = await this.login({ abortSignal: options.abortSignal, reporter: options.reporter });
    }
    const response = await this.fetch(this.getUrl('/api/session/create'), {
        method: 'POST',
        signal: options.abortSignal,
        headers: this.getAuthHeader(),
        credentials: this.options.useCookieAuth ? 'include' : 'omit'
    });
    const body = await response.json();
    return types.CreateRoomResponse.create(body.roomId, body.roomToken, loginToken);
}
```

上游怎么到这：你在 VS Code 里点 “Create” 会走到 vscode 侧的 room service，最终调用 protocol `createRoom()`（见 [open-collaboration-vscode模块](/collaboration_tools/核心模块详解/open-collaboration-vscode模块/open-collaboration-vscode模块.md)）。

下游会发生什么：拿到 `roomId/roomToken` 之后，客户端会用 `roomToken` 去 `connect()` 建立实时连接。

## 4. joinRoom：为什么会“等 Host 点 Allow”

`joinRoom()` 的 HTTP 入口是 `/api/session/join/:roomId`，它先返回一个 `pollToken`，然后客户端进入 `pollJoin()`。关键代码（同文件）：

```ts
const response = await this.fetch(this.getUrl(`/api/session/join/${options.roomId}`), {
    method: 'POST',
    signal: options.abortSignal,
    headers: this.getAuthHeader(),
    credentials: this.options.useCookieAuth ? 'include' : 'omit'
});
const body = await response.json();
const joinToken = body.pollToken;
const joinRoomResponse = await this.pollJoin(joinToken, options);
return { loginToken, roomId: joinRoomResponse.roomId, roomToken: joinRoomResponse.roomToken, workspace: joinRoomResponse.workspace, host: joinRoomResponse.host };
```

你会发现：**Guest 侧 Join 不是“立刻拿 roomToken”，而是“先拿 pollToken，然后一直 poll 等结果”**。那谁来决定这个结果？

答案在 server：`RoomManager.requestJoin()` 会把一个 `peer/join` 的 request 转发给 Host，让 Host 决定 Allow/Deny（源码：`packages/open-collaboration-server/src/room-manager.ts`）：

```ts
const requestMessage = RequestMessage.create(Messages.Peer.Join, this.credentials.secureId(), '', room.host.id, [user]);
const responsePromise = this.messageRelay.sendRequest(room.host, requestMessage, 300_000);
responsePromise.then(async response => {
    if (ResponseMessage.is(response)) {
        const joinResponse = response.content.response as JoinResponse | undefined;
        if (!joinResponse) {
            pollResult.update({ failure: true, code: 'JoinRejected', params: [], message: 'Join request has been rejected' });
            return;
        }
        const claim: RoomClaim = { room: room.id, user: { ...user }, roomClock: ++room.clock };
        const jwt = await this.credentials.generateJwt(claim);
        pollResult.update({ roomId: room.id, roomToken: jwt, workspace: joinResponse.workspace, host: room.host.toProtocol() });
    }
});
```

这段代码解释了你看到的典型现象：“Guest 一直显示 Waiting / Polling”。它不是网络卡住，而是在等 Host 端的 `connection.peer.onJoinRequest(...)` 给回复（VS Code Host 端的弹窗逻辑就在 `packages/open-collaboration-vscode/src/collaboration-instance.ts`）。

## 5. connect：为什么必须带 `x-oct-jwt/public-key/compression`

一旦 `joinRoom()` 最终拿到 `roomToken`，就会进入实时连接 `connect(roomToken)`（同文件）：

```ts
const metadata = await this.getMetaData();
const transportIndex = this.findFitting(metadata.transports, this.options.transports.map(t => t.id));
const transportProvider = this.options.transports[transportIndex];
const keyPair = await Encryption.generateKeyPair();
const transport = transportProvider.createTransport(this.options.url, {
    'x-oct-jwt': roomAuthToken,
    'x-oct-public-key': keyPair.publicKey,
    'x-oct-client': this.options.client ?? 'Unknown OCT JS Client',
    'x-oct-compression': 'gzip'
});
const connection = createConnection({ privateKey: keyPair.privateKey, transport, host });
return connection;
```

这段代码解决的问题是：“在握手阶段把 roomToken 和加密所需的公钥交给 server”。因此 server 端如果收不到 JWT 或公钥，会直接拒绝连接（对应 `connectChannel()` 的校验逻辑）。

## Summary

- `login()` 的关键点是：协议层不管你怎么登录，只通过 `authenticationHandler` 启动流程，然后靠 `pollLogin()` 拿到 loginToken。
- `ensureCompatibility()` 是很多“莫名其妙不工作”的早期止损点：先把 client/server 协议版本对齐。
- `joinRoom()` 之所以会“等”，是因为 server 会把 join request 转发给 Host（`peer/join`），Host 的弹窗回复决定你是否拿到 roomToken。
- `connect(roomToken)` 必须带 `x-oct-jwt/public-key/...`，这是后续消息加密/广播裁剪能成立的前提。
