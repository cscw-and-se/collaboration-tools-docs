# 文件系统代理与远程访问（`oct://` 到底是谁在读写文件）

你作为 Guest 加入协作会话之后，VS Code 会突然打开一个 `oct://` 的工作区。这个现象很容易让人以为“项目把 Host 的文件同步到本地了”，但实际上更准确的说法是：

- Guest 的 VS Code 看到的是一套“远程文件系统”。
- 所有的 `stat/readdir/readFile/writeFile` 都会被转发到 Host 侧去执行。

这一页用一条完整链路把它讲清楚：`joinRoom()` 如何构建 `oct://` workspace，Guest 侧的 `FileSystemProvider` 如何把请求发到网络，Host 侧又如何把请求落到真正的 `vscode.workspace.fs`。

## 1) `joinRoom()` 怎么把工作区变成 `oct://`

Guest join 成功之后，扩展会把 workspace folders 替换成 `CollaborationUri.create(...)` 生成的 `oct://` URI。你可以把它理解成：“把 VS Code 的文件树挂到一个自定义 scheme 上”。核心代码在 `CollaborationRoomService.joinRoom()`：

```ts
const workspaceFolders = (vscode.workspace.workspaceFolders ?? []);
const workspace = roomClaim.workspace;
const newFolders = workspace.folders.map(folder => ({
    name: folder,
    uri: CollaborationUri.create(workspace.name, folder)
}));
const uri = await storeWorkspace(newFolders, this.context.globalStorageUri);
if (uri) {
    await vscode.commands.executeCommand(CodeCommands.OpenFolder, uri, {
        forceNewWindow: false,
        forceReuseWindow: true,
        noRecentEntry: true
    });
    return true;
} else {
    return vscode.workspace.updateWorkspaceFolders(0, workspaceFolders.length, ...newFolders);
}
```

这段代码解决的问题是：“让 Guest 的 VS Code 从此对文件的所有操作都走 `oct://`”。它的下游影响非常大：

- VS Code 文件树展开会触发 `readDirectory()`。
- 打开文件会触发 `stat()` + `readFile()`。
- 保存文件会触发 `writeFile()`。

如果你 join 之后“看到的是空树”或者“打不开文件”，第一反应就应该回到这里：`newFolders` 是否正确、`OpenFolder` 是否执行成功。

## 2) Guest 侧：`CollaborationFileSystemProvider` 如何转发请求

Guest 侧真正提供 `oct://` 文件系统能力的是 `CollaborationFileSystemProvider`，它实现了 VS Code 的 `FileSystemProvider` 接口。

读文件的关键逻辑在 `readFile()`：如果这个 path 已经在 Yjs share 里（说明它被当成“共享文档”同步着），就直接从 Yjs 拿文本；否则就走协议的 `fs.readFile` 请求，让 Host 去读。

```ts
async readFile(uri: vscode.Uri): Promise<Uint8Array> {
    const path = this.getHostPath(uri);
    if (this.yjs.share.has(path)) {
        const stringValue = this.yjs.getText(path);
        return this.encoder.encode(stringValue.toString());
    } else {
        const file = await this.connection.fs.readFile(this.hostId, path);
        return file.content;
    }
}
```

这段代码的上下游很清晰：

- 上游：VS Code 打开文件，调用 `readFile(oct://...)`。
- 下游：要么走 Yjs（共享文本），要么走 protocol 的 `fs.readFile`（远程文件系统）。

另外，`getHostPath()` 这段经常是排障时的关键：它把 `oct:///workspaceName/...` 这种 URI 转回协议层期望的真实 path。

```ts
protected getHostPath(uri: vscode.Uri): string {
    // When creating a URI as a guest, we always prepend it with the name of the workspace
    // This just removes the workspace name from the path to get the path expected by the protocol
    const path = uri.path.substring(1).split('/');
    return path.slice(1).join('/');
}
```

如果你遇到“目录能展开但文件读不到”，很常见的原因就是 path 映射错了（尤其是多根工作区、folder name 与实际 path 不一致时）。这时建议在这段逻辑附近加日志，打印 `uri.path` 和最终 `hostPath`。

## 3) Host 侧：为什么 Host 才是真正读写磁盘的人

协议把文件系统请求转到 Host 后，Host 侧对应的 handler 在 `CollaborationInstance.registerFileEvents()` 里注册。你会看到它最终落到的都是 `vscode.workspace.fs.*`：

```ts
connection.fs.onStat(async (_, path) => {
    const uri = CollaborationUri.getResourceUri(path);
    if (uri) {
        const stat = await vscode.workspace.fs.stat(uri);
        return {
            type: stat.type === vscode.FileType.Directory ? types.FileType.Directory : types.FileType.File,
            mtime: stat.mtime,
            ctime: stat.ctime,
            size: stat.size
        };
    } else {
        throw new Error('Could not stat file');
    }
});
connection.fs.onReadFile(async (_, path) => {
    const uri = CollaborationUri.getResourceUri(path);
    if (uri) {
        const content = await vscode.workspace.fs.readFile(uri);
        return { content };
    } else {
        throw new Error('Could not read file');
    }
});
```

这段代码解决的问题是：“把网络来的请求落回本地文件系统 API”。你可以把它理解成：

- Guest 发 `fs.readFile(hostId, path)`。
- 协议层把它变成一条 request message 发给 Host。
- Host 用 `vscode.workspace.fs.readFile` 读出真实内容，再把结果作为 response 发回去。

因此，文件系统相关问题定位时的经验法则是：

- Guest 侧报错更像“代理层/映射层/权限层”的问题（URI/path/readonly）。
- Host 侧报错更像“真正的文件系统/VS Code API”问题（路径不存在、权限、workpace 没打开）。 

## Summary

- `oct://` 工作区的本质是：Guest 的 workspace folders 被替换成自定义 scheme，所有文件操作都会走 `FileSystemProvider`。
- Guest 侧 `readFile()` 有两条路：Yjs share（共享文档）与远程 `fs.readFile`（转发到 Host）。
- Host 侧 `registerFileEvents()` 把请求落到 `vscode.workspace.fs`，所以 Host 才是真正读写磁盘的人。
