# 房间生命周期管理（创建、加入、离开、关闭、超时）

“房间生命周期”看起来像产品概念，但在这个项目里它就是一组很具体的工程规则：

- Host 离开，房间就关闭。
- Guest 离开，只从房间成员列表移除，并广播 Left。
- join 审批有超时（5 分钟），超时后 poll 结果会变成 JoinTimeout。

这些规则全都写在 `RoomManager` 里。理解它能让你排查很多“看起来像网络问题”的现象（其实是生命周期在起作用）。

## 1) 关闭房间：Host 离开为什么会把所有人踢掉

Host 的 Peer dispose 时会触发 `closeRoom(roomId)`（见 `join()` 的 host 分支）。`closeRoom()` 做了三件事：

1. 广播 `Messages.Room.Closed`。
2. dispose 房间内所有 peer。
3. 从 `rooms/peers` 映射里清理。

```ts
async closeRoom(id: string): Promise<void> {
    const room = this.getRoomById(id);
    if (room) {
        const broadcastMessage = BroadcastMessage.create(Messages.Room.Closed, '');
        this.messageRelay.sendBroadcast(room.host, broadcastMessage);
        for (const peer of room.peers) {
            this.peers.delete(peer.id);
            peer.dispose();
        }
        this.rooms.delete(id);
        this.logger.info(`Deleted room '${room.id}'`);
    }
}
```

这段代码解决的问题是：“Host 是房间的锚点”。所以你看到 Guest 端弹 “session closed” 并退出工作区，不是 VS Code 扩展自己决定的，而是房间状态机决定的。

## 2) 离开房间：Guest 离开为什么只广播 Left

`leaveRoom(peer)` 的策略也很明确：Host 离开等价于关闭房间；Guest 离开只做成员移除与广播。

```ts
async leaveRoom(peer: Peer): Promise<void> {
    const room = this.getRoomByPeerId(peer.id);
    if (!room) {
        return;
    }
    if (peer.host) {
        this.closeRoom(room.id);
    } else {
        try {
            const broadcastMessage = BroadcastMessage.create(Messages.Room.Left, '', [peer.toProtocol()]);
            this.messageRelay.sendBroadcast(peer, broadcastMessage);
        } catch (err) {
            this.logger.error('Failed to send leave broadcast', err);
        }
        // Remove the peer from the room as the last step
        this.peers.delete(peer.id);
        room.removeGuest(peer.id);
    }
}
```

这段代码解决的问题是：“Guest 的离开不应该影响房间存在”。因此当你排查“为什么某个 guest 离开后其他人还在”，这是正常行为。

## 3) join 审批超时：`requestJoin()` 里的 5 分钟到底在清理什么

join 审批走的是“发 request 给 Host + 客户端轮询 poll”。因此 server 必须维护一个 `pollResults`，并在超时后清理它。

下面这段代码把超时与清理写得非常明确：

```ts
const responseId = this.credentials.secureId();
const timeout = setTimeout(() => {
    pollResult.update({
        code: 'JoinTimeout',
        message: 'Join request has timed out',
        params: [],
        failure: true
    });
    pollResult.dispose();
}, 300_000); // 5 minutes of timeout
const updateEmitter = new Emitter<JoinRoomResponse | RoomJoinInfo>();
const pollResult: JoinPollResult = {
    update: result => {
        pollResult.result = result;
        updateEmitter.fire(result);
    },
    onUpdate: updateEmitter.event,
    dispose: () => {
        updateEmitter.dispose();
        this.pollResults.delete(responseId);
        clearTimeout(timeout);
    }
};
this.pollResults.set(responseId, pollResult);
```

这段代码解决的问题是：“join 审批是一个跨时间的流程，必须可轮询、可超时、可清理”。

当你排查 join timeout，建议用一句话概括它在等谁：

- **它在等 Host peer 对 `Messages.Peer.Join` request 的响应**。

## Summary

- Host dispose 会触发 `closeRoom()`：广播 Closed + dispose 所有 peer。
- Guest dispose 会触发 `leaveRoom()`：广播 Left + 从成员列表移除。
- join 审批超时（5 分钟）会更新 poll 状态为 JoinTimeout，并清理 `pollResults`。
