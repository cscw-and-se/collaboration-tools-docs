# 房间与用户管理机制（Room、Peer、Host/Guest 的真实含义）

在协作系统里，“房间”不是一个抽象名词，它是 server 端的第一等公民：它决定了消息广播范围、谁有权限、谁是 Host、谁能审批加入。

这一页用 `RoomManager` 的核心方法，把 room 的生命周期与 join 流程讲清楚。你读完之后，至少应该能回答三件事：

- Host 创建房间时到底生成了什么（roomId 与 JWT）？
- Guest 加入房间为什么要走 “WaitingForHost”？
- Peer 是怎么挂到 room 上的？断线重连算不算同一个 Peer？

## 1) 创建房间：`prepareRoom()` 生成 roomId + roomClaim JWT

Host 创建房间的第一步是 `prepareRoom(user)`。它做的事情非常明确：

- 生成一个 `id` 作为 roomId（邀请码）。
- 构造 `RoomClaim`（带 `host: true`、`roomClock: 0`），并签一个 JWT。

```ts
async prepareRoom(user: User): Promise<PreparedRoom> {
    const id = this.credentials.secureId();
    const claim: RoomClaim = {
        room: id,
        user: {
            id: user.id,
            name: user.name,
            email: user.email
        },
        host: true,
        roomClock: 0
    };
    const jwt = await this.credentials.generateJwt(claim);
    return { id, jwt };
}
```

这段代码解决的问题是：“让 Host 拿到一个可用于连接的房间 token”。你需要注意：

- `roomId` 是人类用的邀请码（会被复制给别人）。
- `jwt` 是连接凭证（真正让 server 认你的东西）。

## 2) 加入房间：`join()` 里 Host 与 Guest 走完全不同的分支

`join(peer, roomId)` 是房间状态机的核心。它把 Peer 挂到 room 上，并在 Guest 加入时广播成员变更。

```ts
async join(peer: Peer, roomId: string): Promise<Room> {
    let room: Room | undefined;
    if (peer.host) {
        room = new Room(roomId, peer, []);
        this.rooms.set(room.id, room);
        this.peers.set(peer.id, room);
        peer.onDispose(() => {
            this.closeRoom(room!.id);
        });
    } else {
        room = this.rooms.get(roomId);
        if (!room) {
            throw this.logger.createErrorAndLog(`Could not find room to join from id: ${roomId}`);
        }
        const broadcastMessage = BroadcastMessage.create(Messages.Room.Joined, '', [peer.toProtocol()]);
        this.peers.set(peer.id, room);
        room.guests.push(peer);
        this.messageRelay.sendBroadcast(peer, broadcastMessage);
        peer.onDispose(() => {
            this.leaveRoom(peer);
        });
    }
    // Send the identity info to the user
    const infoNotification = NotificationMessage.create(Messages.Peer.Info, '', peer.id, [peer.toProtocol()]);
    this.messageRelay.sendNotification(peer, infoNotification);
    return room;
}
```

这段代码解决的问题是：“把一个 Peer 放进房间，并让房间里其他人知道”。你读它时建议盯三个点：

- Host 分支里 `peer.onDispose(() => closeRoom)`：Host 断线/退出会关闭整个房间。
- Guest 分支里 `sendBroadcast(Messages.Room.Joined)`：成员加入通知是广播实现的。
- 最后一定会发 `Messages.Peer.Info`：这是 server 告诉客户端“你是谁（peerId 等元信息）”的重要通知。

对应的代码就在 `join()` 末尾（无论 Host/Guest 分支都会走到这里）：

```ts
const infoNotification = NotificationMessage.create(
    Messages.Peer.Info,
    '',
    peer.id,
    [peer.toProtocol()]
);
this.messageRelay.sendNotification(
    peer,
    infoNotification
);
```

## 3) Guest 为什么要等 Host：`requestJoin()` 的轮询状态机

Guest join 并不是一锤子买卖。它还要走 `requestJoin(room, user)`：把 join 请求发给 Host，让 Host 决定 allow/deny，并生成给 Guest 的 roomToken。

这段逻辑比较长，但你只要记住它维护的状态机就够了：

- `WaitingForHost`：已把 request 发给 Host，等待 Host 弹窗审批。
- `JoinTimeout`：5 分钟没有结果，poll 结束。
- `JoinRejected`：Host 拒绝或返回空响应。
- `JoinRoomResponse`：Host 允许，server 给 Guest 签发 roomToken（JWT）。

具体实现可以对照 [open-collaboration-server 模块](/collaboration_tools/核心模块详解/open-collaboration-server模块/open-collaboration-server模块.md) 里贴的 `requestJoin()` 代码片段；对应的 VS Code 端弹窗逻辑在 [项目概览](/collaboration_tools/project_overview.md) 里也贴过。

## Summary

- `prepareRoom()` 生成 roomId（邀请码）和 roomClaim JWT（连接凭证）。
- `join()` 里 Host/Guest 分支差异很大：Host 创建 room；Guest 加入 room 并广播 Joined。
- join 后一定会发 `Peer.Info` 通知，让客户端拿到自己的 peerId 等信息。
- Guest join 要等 Host，是 `requestJoin()` 的轮询状态机决定的，而不是 UI 凭空编出来的。
