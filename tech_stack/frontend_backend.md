# 前后端开发

当你开始参与一个真正的软件项目时，常会听到“这个项目是**前后端分离**的”。这篇文章解释它是什么意思、为什么这么设计，以及学生项目里怎么落地。

## 前端和后端分别负责什么

一个完整的应用可以分成两部分：

**前端 (Frontend)**：用户直接看到和操作的部分。

- 负责界面展示和交互：页面布局、样式、按钮点击等。
- 常用技术：`HTML`、`CSS`、`JavaScript`，以及 `Vue.js`、`React`、`Angular` 等框架。
- 核心职责：把内容呈现给用户，并响应用户操作。

**后端 (Backend)**：在服务器上运行、用户看不到的部分。

- 负责业务逻辑、数据存储和安全校验。
- 常用技术：`Java`、`Python`、`Go`、`Node.js` 等语言；`MySQL`、`MongoDB` 等数据库；`Nginx` 等服务器软件。
- 核心职责：处理请求、读写数据、保证服务稳定与安全。

## API：前后端之间的约定

前端和后端通过 **API（Application Programming Interface）** 通信。可以把它理解成一份约定好的“订单格式”：

前端把请求整理成固定的结构发给后端，例如：

```json
{ "table": 5, "item": "steak", "doneness": 8 }
```

后端处理完再按约定返回结果。双方只要遵守同一套接口规范，就不需要关心对方内部怎么实现：前端不用知道数据怎么存，后端也不用关心界面长什么样。

## 什么是前后端分离

前后端分离，就是**前端和后端是两个独立开发、独立部署的项目**，只通过 API 对接。

好处主要有三点：

1. **可以并行开发**：接口一旦确定，前端专注界面和交互，后端专注业务和数据，互不等待。
2. **一套后端支持多种前端**：同一个后端可以同时服务于网站、手机 App、小程序等多个前端。
3. **技术栈解耦**：只要 API 不变，可以单独升级前端框架或替换后端实现，互不影响。

## 学生项目里怎么落地

初次尝试可以按这个流程：

1. **先定义 API**：写代码前，前后端一起确定需要哪些接口，各自接收什么参数、返回什么数据，并落成一份简单的接口文档。
2. **前端用 Mock 数据**：后端还没好时，前端根据接口文档自己造一些假的 JSON 数据，先把界面做出来。
3. **后端实现接口**：后端按同一份文档开发数据库和业务逻辑。
4. **联调**：后端接口完成后，前端把数据来源从 Mock 切到真实 API，前后端一起测试。

前后端分离对于学生项目最大的价值，是强制做清晰的模块化分工，避免所有代码混在一起。前期多花一点时间定义接口，换来的是后续可以并行开发。
