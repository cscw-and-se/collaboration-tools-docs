## 1. 三个基础概念

- **哈希函数**：把任意大小的数据映射成固定长度的摘要（如 SHA-256），不可逆。常用来校验文件完整性：
  ```bash
  sha256sum file.iso
  ```
  把输出和官方给出的值对比，就能判断文件是否被改动。
- **对称加密**：加密和解密使用同一把密钥，速度快，适合加密大量数据。
- **非对称加密**：使用一对密钥，公钥加密、私钥解密（也可以私钥签名、公钥验证）。SSH 免密登录和 HTTPS 都建立在它之上。

你不需要自己实现加密算法，但要理解这几个概念各自解决什么问题。

## 2. SSH 密钥

```bash
ssh-keygen -t ed25519
```

把生成的 `.pub` 公钥内容放到服务器的 `~/.ssh/authorized_keys`，私钥留在本地并设置 passphrase。这样登录更安全，也方便与 GitHub / GitLab 通信。

## 3. 密码与认证

密码的安全性取决于不可预测性，而不是复杂符号的数量。四个随机单词组成的短语通常比 `P@ssw0rd123` 更难被破解，也更好记。

- 用密码管理器（如 Bitwarden、1Password）生成并保存长且随机的密码，你只需要记住一个主密码。
- 开启双重认证（2FA / 硬件密钥），即使密码泄露，攻击者也无法直接登录。

## 4. 开发中的常见问题

- **不要把密钥写进代码**。API 密钥、数据库密码等应放在 `.env` 文件中，并加入 `.gitignore`。
- **定期检查依赖漏洞**并更新：
  ```bash
  npm audit
  pip-audit
  ```

## 5. 网络

- 始终使用 HTTPS，它同时提供加密和服务器身份验证。
- 在不信任的网络环境下，用 VPN 或 SSH 隧道转发流量，避免中间人攻击。

## 小结

安全更多是习惯和流程问题，而不是一次性配置。把密钥管理、2FA、依赖更新做成日常习惯，成本很低但收益很大。
