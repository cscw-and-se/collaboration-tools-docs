# 为什么使用 AI 编程

> 本文于 2026 年 9 月做过一次更新。AI 工具变化很快，具体产品强弱会继续变化，但“尽早把 AI 接进自己的开发流程”这个判断没有变。

从我个人的经验出发，我**强烈推荐**每一位开发者都尽早把 AI 用进日常工作，而不只是观望。

时间拉回到 2022 年底，GPT-3.5 刚发布的时候，AI 的编程能力还很有限，基本只能补全单行命令或简单的代码片段，稍微复杂一点的需求就容易出错。真正的转折出现在 2024 年底到 2025 年：Claude、Codex 这类 Coding Agent 出现之后，AI 的编程能力和“长时间执行”能力都有了明显提升。它不再只是接一句话、写一段代码，而是能围绕一个目标连续工作——自己找文件、改代码、跑测试，中途失败了还能回头修正。到今天，大语言模型（LLM）在理解、分析和生成代码上的进步，已经超出很多人当初的预期。

在很多场景下，我甚至认为 AI 生成的代码在健壮性、可读性和最佳实践方面，**已经超过了我们自己随手写出的代码**。我个人的工作流也因此发生了改变：更多时候，我会先用自然语言清晰地描述需求、思考可能的技术选型，然后与 AI 交流，让它生成具体的实现代码。这种“人机协作”的模式，往往能产出质量更高的代码和更完善的文档。

实际上，你正在阅读的这系列文档，也正是采用这种方式完成的：由我先撰写核心思想和草稿，再交由 AI 进行润色和扩展，最终的语言表达和结构都因此得到了优化。

## AI 能帮你做什么

AI 的用途远不止“代码补全”，日常开发里至少能帮你做这些事：

* **解释代码和概念**：看不懂的代码、不熟的概念或第三方库，直接把片段或问题丢给 AI，比在网页里翻半天要快。

* **排查报错**：程序崩溃时，把完整的错误日志（Error Log）和相关代码给它，通常能较快定位问题，并给出修复建议。

* **技术选型**：不确定新项目用什么技术栈，把你的需求（用户量、功能复杂度、部署环境等）告诉它，让它分析并推荐合适的前后端方案。

* **写注释和文档**：让它帮你写的函数或模块补上注释、`README.md`，这是保证项目可维护性的关键一步。

* **直接生成代码**：需求明确时，可以让它以 Agent 的模式直接生成代码文件。这里有一个实用技巧：
    > 如果需求描述（Prompt）比较模糊，可以先让一个 AI（比如网页版的 ChatGPT 或 Claude）帮你把模糊的想法，**重写成一个清晰、完整、结构化的 Prompt**，然后再将这个高质量的 Prompt 交给 AI Agent 来执行代码生成任务，效果会好得多。

## 从网页版，到你的开发环境

很多人的 AI 使用体验还停留在网页版的 ChatGPT 或 Gemini 上：复制一段代码过去，等它回复，再手动贴回编辑器。对开发者而言，**更高效的方式是让 AI 直接运行在你的电脑里、你的项目里**——可以是 IDE 里的插件，也可以是终端里的 Coding Agent。

本地工具和网页版最大的区别，在于它既有**上下文感知（Context Awareness）**，又有**动手能力**。以终端里的 Coding Agent 为例，它已经不太依赖“先把整个代码库索引成一张代码图谱”这种做法，而是像人一样，按需使用工具去探索和修改项目，形成一个循环：

- 用 `grep`、`glob`、读文件等命令**查找**相关代码，理解现状；
- 用编辑工具**写入**或修改文件；
- 自己**运行**编译、测试和 lint 命令；
- 读取命令的输出，判断是否通过；如果失败，就回到第一步继续调整。

如此循环，直到任务完成，或者它判断自己搞不定、需要你来决定。

## 值得关注的 AI 编程工具

以下是一些我个人比较推荐的工具。**这份清单一定有时效性**：AI 工具几个月就是一轮洗牌，今天的主力方案，半年后未必还是。所以不要把它当成固定答案，更重要的是保持开放心态，看到新东西就自己试一试。

* **[Claude Code](https://claude.ai/code)**
    * **简介**：Anthropic 官方的 CLI 编程助手，直接在终端里运行，能读取整个代码库、执行命令、修改文件。支持 Plan 模式（先规划再执行）和 `@` 上下文引用。
    * **推荐理由**：它非常适合做复杂代码库里的持续协作：解释源码、拆任务、改代码、补文档、跑测试都很顺。文风也比较简洁直接，适合需要技术深度和表达质量的场景。
    * **适合谁**：习惯终端、愿意让 Agent 深度参与项目的人。

* **[CodeX](https://openai.com/zh-Hans-CN/codex/)**
    * **简介**：OpenAI 的 AI Coding Agent，运行在本地/云端项目根目录，可直接读写代码、执行命令、运行测试并生成提交信息，支持“计划执行 + 实时反馈”的工作模式。
    * **推荐理由**：相比纯聊天式模型，CodeX 拥有完整的命令执行环境（CLI Harness），能够读取整个仓库、批量编辑文件、解释终端输出并持续迭代，适合需要落地代码、修复 Bug 或撰写技术文档的场景。
    * 后面的文档会提到性价比较高的中转站和使用方式。

![](assets/2025-12-14-16-55-09.png)

* **[OpenCode](https://github.com/anomalyco/opencode)**
    * **简介**：开源的终端 AI 编程助手，支持接入多种模型（Claude、GPT、Gemini、本地模型等）。核心卖点是把代码和上下文留在本地。
    * **推荐理由**：本地优先、模型可自选，配合社区增强配置可以搭出一套很顺手的终端工作流。

* **[DeepSeek Harness (dsh)](https://github.com/deepseek-ai/deepseek-harness)**
    * **简介**：DeepSeek 官方开源（MIT）的 Agent Harness，2026 年 8 月发布开发者预览版，设计理念是“一切皆插件”——模型、工具、技能、会话、沙箱、UI 都可以替换。
    * **推荐理由**：它把 Agent 的各个部件都拆成了插件，非常适合拿来理解一个 Harness 到底由什么组成，也很适合动手改造。国内网络环境下获取和使用都比较方便。
    * **适合谁**：想深入理解 Agent 架构，或者想自己定制 Agent 工作流的人。

* **[Pi (π)](https://github.com/earendil-works/pi)**
    * **简介**：由 Mario Zechner（libGDX 作者）发起的开源终端 Coding Agent Harness，同样采用 MIT 协议。走极简路线，系统提示很短，强调低 token 消耗和可扩展。
    * **推荐理由**：代码量相对可控，是“轻量级 Harness 应该长什么样”的一个好样本。支持接入多家模型，可以作为 Claude Code、CodeX 之外的另一种选择。

* **[Cursor](https://www.cursor.com/)**
    * **简介**：一款“AI-First”的代码编辑器，围绕 AI 重新设计了许多交互，代码库索引和问答能力非常强大。
    * **获取**：提供年度教育优惠，但可能需要国外的教育邮箱进行验证。（笔者的建议：很多 AI 工具的免费途径一般都会先松后紧，因为申请的人会越来越多，所以看见有合适的机会不要错过）

![](assets/2025-12-14-16-55-33.png)

* **[Trae (字节跳动 IDE)](https://www.trae.ai/)**
    * **简介**：字节跳动推出的 AI IDE。其特点是根据地区不同，集成了不同的后端大模型。国内版支持豆包（Doubao）、DeepSeek 等模型，海外版则支持 Claude 等。

* **[GitHub Copilot](https://github.com/features/copilot)**
    * **简介**：由 GitHub 推出的 AI 编程助手，深度集成于 VS Code 等主流编辑器中，是很多人最早接触的 AI 编程工具。
    * **推荐理由**：获取难度低，补全体验顺手，可以通过 **GitHub Education** 学生包免费获取，后续章节会介绍申请方法。
    * **2026 年 9 月更新**：如果只是把它当作 VS Code 里的补全插件，相较于 Claude Code、CodeX 这类 Agent，它已经不太像主力方案了。作为入门工具，或者日常编辑器里的轻量补全仍然够用，但建议尽早接触完整的 Agent 工作流。

![](assets/2025-12-14-16-56-14.png)

* **[命令行 AI 工具 (CLI)](https://github.com/google/gemini-cli)**
    * **简介**：对于热爱终端的开发者，`gemini-cli` 等工具可以把大模型的能力直接带到命令行中，方便快速查询或执行脚本任务。
    * **2026 年 9 月更新**：Gemini CLI 现在存在感相对弱一些，不是我最推荐的主力 AI coding 工具。但它适合轻量命令行问答、Google 生态体验、多模态尝试，国内获取难度也相对低，可以作为补充工具。

**注意**：部分工具的流畅使用可能需要稳定的互联网环境，在此不展开讨论。

## 保持开放心态，持续探索

最后，我想强调的是，AI 领域的发展日新月异，今天最好的工具可能在三个月后就被超越。这份文档里的工具清单，本身也带有很强的时效性——**一旦停止更新，很快就会落后**。所以比“记住某个工具”更重要的，是保持对前沿信息的关注，并亲手去试，找到当下最适合自己的那一套。

就我个人的体验来说（截至 2026 年 9 月），我日常主要用的是 **CodeX**、**Claude Code**，以及 **OpenCode 搭配 DeepSeek Flash**；配置层面会用 **CC Switch** 来做不同工具、模型之间的切换与路由管理。偶尔也会用 **Gemini** 和 **NotebookLM** 做一些辅助工作。通常，闭源的商业模型在综合能力上会优于当前的开源模型，而国外顶尖公司的模型会略胜一筹。

但无论如何，最重要的还是**现在就开始用**。把 AI 接进日常工作流，你会慢慢发现自己做事的方式变了。
