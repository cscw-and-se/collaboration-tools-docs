# 用 AI 写论文：先定标准，再交给 AI

用 AI 写论文最常见的问题，是初稿看上去很顺，读起来却处处是 AI 腔。词是翻译腔，句子长而绕，段落堆满概括性的话，整篇没有一个具体的例子。解决办法不是反复让 AI 润色，而是你先想清楚自己对好文字的标准是什么，再把标准告诉 AI。

这篇教程分三步。第一步是你自己在审稿时应该看哪些方面（品味从哪里来），第二步是怎样把这些方面写成提示词，第三步是装什么 skill 让 AI 默认就注意到这些方面。

## 适合谁读

- 正在写毕业论文、小论文或技术报告，并且已经在用 AI 帮忙的同学。
- 发现 AI 改出来的文字读着别扭，却说不清哪里别扭的同学。

## 先分清两件事

AI 写作有两类问题，处理方式不同。

第一类是**内容问题**，比如逻辑跳跃、论据不足、没有例子、术语没有定义。这类问题要靠你自己的判断，AI 只能帮你查漏。

第二类是**表达问题**，比如翻译腔词汇、堆砌的抽象名词、过度的排比和破折号。这类问题有明确模式，可以写成规则交给 AI 检查。

后面的 skill 主要处理第二类。第一类需要你自己在审稿时有标准，这就是下一节要讲的内容。

## 第一步：审稿时从哪些方面看

下面这些方面来自我在改毕业论文时反复遇到的问题。你不必全部照搬，但建议每改完一章，按这个清单过一遍，并逐步补上自己的条目。

### 1. 词汇是否是翻译腔

AI 很喜欢把英文术语逐字翻成中文，读起来像机器翻译。

| 翻译腔 | 更自然的说法 |
|---|---|
| 管线（pipeline） | 处理流程 |
| 引擎（engine） | 具体说明是什么工具或程序 |
| 落盘 | 写入磁盘 |
| 长尾 | 偶尔较慢的情形 |
| 守卫、闸门 | 直接说它做了什么，比如拒绝请求、暂停写入 |

判断方法是，把这个词读给不了解背景的同学听，他能不能一次听懂。听不懂就换成直接描述动作的说法。

### 2. 句子结构是否顺

- **语序**。主语和重点放前面，避免倒装。
- **长定语**。英文直译的长定语要拆成两句。
- **抽象名词堆叠**。比如“依赖类型覆盖有限”，应说清楚是什么有限。
- **先说能力再说约束**。先写允许做什么，再写限制在哪里。
- **比较句紧贴对象**。避免读者误解比较的是谁和谁。
- **不用突兀的转折句开段**。直接把要讲的对象说出来。
- **段末不加口语化的预告句**。章节衔接交给标题和章首引言。

### 3. 语体是否一致

去掉 AI 腔以后，容易矫枉过正变成口语。论文要通俗，但要保持书面语。比如“拦住”改成“拦截”，“从哪里来”改成“来源”，“好坏”改成“准确程度”。

### 4. 是否有真实的信息

- 每句话是否有实际信息，还是在复述上一句。
- 数字是否有分子分母，比如“289 条请求中有 4 条被转为审批”，比“误拦率很低”有用得多。
- 近似说法和数字是否一致，42.9% 写成“四成以上”，不写成“近一半”。
- 同一个指标在全文里是否用同一个名字。

### 5. 术语和例子

- 新术语首次出现时是否有定义，最好配一个例子。
- 一章是否有一个贯穿全章的例子，图和正文都围绕它。
- 术语改名后，正文、图、摘要、附录是否都同步改了。

### 6. 是否混入了作者自己的工作笔记

论文面向读者，不面向写代码和跑实验的人。内部编号、提示词版本号、实验流程代号、提交哈希、费用和调用次数，这些适合放在附录或项目记录里，正文用名称和一句话描述。

### 7. 是否在自我削弱

学位论文和投稿论文通常不主动给评审提供攻击点。实验正文里“这组结果只能说明……”“不能推广到……”“这是本方法的缺陷”这类句子要谨慎使用。适用前提可以写成一句前提条件，不要写成局限。需要提的不足，放到后续工作里，用扩展方向的口吻。

这一条是否适用，取决于你的学位论文要求和投稿期刊的规范，请先问导师。

### 8. 图表

- 抽象概念和流程是否配了图，先后顺序用时序图。
- 每张图在正文里有引用和一两句说明，说明与图中例子一致。
- 表格只放支撑论点的列，不放实现层细节。
- 图中的措辞与正文一致。

### 9. 标点

我个人的要求是不用破折号，不用冒号引出列表，不用引号强调术语。这几种写法是常见的 AI 文本特征，改成逗号、分号或完整的句子即可。

## 第二步：用提示词让 AI 注意到这些方面

提示词有三种用法，按场景选。

### 用法一：写作前，先告诉 AI 标准

把上面你认同的条目整理成一段话，放在对话开头。下面是一个可以直接改的模板。

```md
你是我的论文写作助手。接下来我会给你论文草稿，请按下面的标准处理。

写作标准：
1. 面向没有背景的读者，术语首次出现必须定义，并尽量配例子。
2. 使用书面语，但不要翻译腔。不要使用“管线”“引擎”“落盘”这类英文直译词。
3. 不使用破折号，不用冒号引出列表，不用引号强调术语。
4. 每句话都要有信息量，不要复述上一句，不要写空泛的总结句。
5. 数字要带分子分母，近似说法要与数字一致。
6. 不要编造数据、引用和结论。原文没有的信息，请标注“需要作者补充”。
7. 保持我原有的结论、否定、条件和确定程度。“可能”不能改成“确定”。

处理方式：先指出问题，再给修改建议，不要直接重写全文。
```

### 用法二：写完后，让 AI 只挑问题不改写

很多时候你不想让 AI 改你的文字，只想知道哪里有问题。

```md
请阅读下面这一节，按以下清单逐条检查，只列出问题和所在句子，不要改写。

检查清单：翻译腔词汇、语序别扭的句子、抽象名词堆叠、口语化表达、没有定义就使用的术语、没有信息量的句子、数字与近似说法不一致、破折号和冒号的使用。

输出格式：每条问题包含原句、问题类型、一句话理由。
```

这个用法的好处是你保留了修改的主动权，AI 只负责查漏。

### 用法三：让 AI 帮你积累清单

每次改稿时，把你手动改掉的词和句子对照贴给 AI，让它归纳成规则。

```md
下面是我这一轮改稿中的修改对照（左边是原文，右边是改后）。请归纳其中的规律，整理成可复用的检查清单，分成词汇、句式、语体三类。
```

积累几轮以后，你就有了一份自己的审稿清单，也可以进一步做成下一节的 skill。

### 一个自查小技巧

词汇类问题可以用 `grep` 在本地检查，不依赖 AI，结果更稳定。

```bash
grep -n "管线\|引擎\|守卫\|闸门\|落盘\|长尾\|换言之" 第3章.md
```

```bash
grep -n "——\|：$" 第3章.md
```

第一条检查翻译腔词汇，第二条检查破折号和以冒号结尾的行。词表按你自己的论文积累即可。

## 第三步：装 skill，让 AI 默认就注意

提示词每次都要贴，很麻烦。skill 可以让 Agent 在写作任务中自动加载这些规则。下面两个是网上现成的中文 skill，我核对过它们的说明。

### humanizer-zh

- 仓库：[op7418/Humanizer-zh](https://github.com/op7418/humanizer-zh)
- 作用：润色已有的中文文章，减少空话、重复和模板化表达，同时保留事实、确定程度和作者的声音。
- 规则要点：不编造功能、数据、来源或经历，保留否定、条件、归因和完成状态，排比、破折号、连接词按作用判断而不是一律删除，默认只输出最终稿。
- 安装（Claude Code）：

```bash
npx skills add https://github.com/op7418/Humanizer-zh.git
```

安装后重新加载 skills，输入 `/humanizer-zh` 即可使用。

### 说人话（shuorenhua）

- 仓库：[MrGeDiao/shuorenhua](https://github.com/MrGeDiao/shuorenhua)
- 作用：中文优先的改写 skill，删掉套话、重复铺垫和生硬句式，保留数字、日期、条件、承诺和作者口气。
- 特点：提供三档改动范围，分别是自由调整、保留结构、只在原位改。也可以只标出问题而不改写。原文没有问题时原样返回。
- 安装（Claude Code）：

```bash
/plugin marketplace add MrGeDiao/shuorenhua
/plugin install shuorenhua@shuorenhua
```

Codex、Cursor 等支持 skills 的工具，可以用下面的命令安装，加 `--global` 装到用户目录。

```bash
npx skills add MrGeDiao/shuorenhua
```

### 使用这些 skill 的注意事项

- 这两个 skill 都明确说明，它们是编辑指导，不是 AI 检测程序，也不保证通过 AI 检测。不要把它们当作规避检测的工具。
- 它们面向通用中文文本。学术论文有自己的规范，比如术语必须统一，所以改完以后要自己再核对一遍术语和数字。
- 英文论文可以用 `writing-anti-ai` 这类同时支持英文的 skill，或者用提示词处理。
- skill 的版本更新很快，上面的说明基于 2026 年 11 月我看到的 README，安装前请以仓库页面为准。

### 把自己的标准做成 skill

通用 skill 解决不了你的论文里特有的术语和规范。当你的审稿清单积累到一定程度，可以让 Agent 帮你把它写成一个自己的 skill，放在 `~/.claude/skills/` 下。最省事的做法是把清单发给 Agent，直接说“请把它做成一个 skill”。

## 推荐的整体流程

1. 你自己写骨架和关键论点，先口述也可以，见 [AI 使用实践](/ai_coding/ai_practice_and_boundaries.md) 中的语音输入部分。
2. 让 AI 在你的标准下扩写成初稿，或者只做结构调整。
3. 用提示词的用法二检查问题，自己决定怎么改。
4. 用 humanizer-zh 或说人话做一轮表达层的润色。
5. 用 `grep` 做本地自查，核对术语、数字和引用。
6. 引用文献一定要自己核对真实性，不要让 AI 生成参考文献。

## 常见问题

**AI 改完以后事实变了怎么办？** 要求 AI 保留否定、条件和确定程度，并在改完后让它列出改动前后信息有变化的句子。人工核对数字和引用。

**用了 skill 还是有 AI 腔？** skill 处理的是已知模式。你的审稿清单才是长期有效的东西，把新发现的问题补进清单。

**会不会被查出来？** 学校和期刊对 AI 使用的要求各不相同，请先阅读相关规定，并按要求披露。本教程的目的是提升文字质量，不是规避检查。
