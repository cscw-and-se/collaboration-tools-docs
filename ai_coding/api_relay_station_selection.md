这篇文档记录的是 2026 年 9 月前后的使用经验，主要面向想在国内网络环境里稳定使用 Claude、GPT、Gemini、DeepSeek、GLM 等模型的同学。

选中转站，核心就看四件事：**质量、价格、稳定性、发票**。质量是模型真不真、响应正不正常；价格要透明、能对得上账单；稳定性看长任务会不会断、限速、排队；发票主要关系到团队和报销。模型也不用一刀切，编码、文书、低预算任务可以组合不同的模型。

这些只是当前时间点比较好用的，不代表永远推荐。选之前先做三件事：

1. 小额充值，别一上来就充很多。
2. 用自己的真实任务跑一轮，不要只看空对话。
3. 看账单里输入、输出、缓存、倍率是否清楚。

如果需要报销或团队使用，还要确认能不能开发票、支持对公、按项目或 Key 分账。

## 按任务选择模型

不一定要“永远用最贵的模型”，按任务拆开更划算：

| 任务类型 | 推荐模型 |
|---|---|
| 编码 | 尽量用最新的旗舰模型，比如 GPT 6 |
| 文字 / 文书 | DeepSeek Flash 或 Claude Opus 4.6 |

编码对推理和工具调用能力要求高，用最新的大模型更稳，也少来回返工。文字类任务里，DeepSeek Flash 便宜够用，Claude Opus 4.6 的表达更自然、更“不像 AI”，按预算选就行。

## 编码任务不要只算单次价格

编码任务里，“80 分模型”和“90 分模型”的差距，有时候像“0 分”和“100 分”。

差一点的模型可能要反复读文件、反复调用工具、反复修错，十几轮才做完；好模型两三轮就能定位问题、改完代码、跑完测试。单轮便宜，但多出来的调用次数和 token 会把便宜吃掉，还搭上你的注意力。

所以算账不只看每百万 token 的单价，还要看：

- 完成同一个任务需要几轮。
- 是否经常改错文件或跑偏。
- 能不能自己读懂报错并修复。
- 会不会主动跑测试和验证。
- 你要花多少时间盯着它纠偏。

写代码、改复杂项目、做多文件重构，尽量用更好的模型；简单问答、资料整理、格式转换，便宜模型就够了。

## 选择中转站时的检查清单

第一次用一家中转站，可以按这个顺序看：

1. **注册和充值**：是否支持小额充值，有没有最低门槛。
2. **模型覆盖**：是否支持你要用的 Claude、GPT、Gemini、DeepSeek、GLM 等。
3. **工具适配**：是否给出 Claude Code、Codex、Cursor、OpenAI-compatible Base URL 的配置方式。
4. **真假检测**：用 Hvoy 或自己的测试提示看模型行为。
5. **价格结构**：分别看输入、输出、缓存、倍率、会员折扣和套餐限制。
6. **稳定性**：用真实项目跑一两个小时，观察延迟、断连、限速和错误率。
7. **账单透明度**：能否追踪每个 Key、每次调用、每个模型的消耗。
8. **售后与发票**：团队使用时重点看客服响应、发票、对公和群公告。
9. **资金风险**：不大额囤余额，不长期依赖单一站点。
